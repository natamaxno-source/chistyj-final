# Скилл проекта «Чистый Финал»

Клининговое приложение для компании **«Чистый Финал»** (Новосибирск): лендинг со встроенным калькулятором стоимости уборки, приём заявок из чат-бота и передача их в админ-панель для персонала.

## Публичные ссылки
- Лендинг: https://chistyyfinal.netlify.app
- Админ-панель: https://chistyyfinal.netlify.app/admin
- Репозиторий: https://github.com/natamaxno-source/chistyj-final

## Как устроен проект

**Всё в одном проекте: лендинг + приложение (серверная часть) + админ-панель.**

| Слой | Что это / технологии |
|---|---|
| Лендинг | `deploy/index.html` — главная страница с калькулятором и чат-ботом |
| Админ-панель | `deploy/admin.html` + `admin.js` + `admin.css` — заявки, тарифы, бригады |
| Backend | Netlify Functions (Node.js) в `netlify/functions/` |
| База данных | Netlify Blobs (`orders`, `settings`) |
| Хостинг | Netlify (статический сайт + serverless) |
| Frontend | HTML + CSS + Vanilla JS |

## Структура проекта

```
deploy/                 — статика: index.html (лендинг), admin.html (админка), calc.html (демо-калькулятор)
netlify/functions/      — серверные функции
  webhook-chat.js       — приём заявок из чат-бота (POST)
  orders.js             — чтение/обновление заявок (GET, PATCH)
  data.js               — тарифы, услуги, бригады (GET, PUT)
netlify.toml            — маршруты /api/* → функции, папка деплоя
scripts/build.js        — сборка (статика деплоится как есть)
```

## Данные

Хранятся в **Netlify Blobs**:
- store `orders` — заявки клиентов;
- store `settings` — ключи `tariffs`, `services`, `teams`.

При первом обращении автоматически создаются базовые данные: 3 тарифа (Лайт, Стандарт, Премиум), 5 дополнительных услуг, 3 бригады.

## API

**Публичный:**
- `POST /api/webhook/chat` — приём заявки из чат-бота. Формат:
  `{ name, phone, property_type, area, tariff_id, date }`
  Ответ: `{"ok":true,"order":{...}}`

**Админ-панель:**
- `GET /api/orders` — список заявок
- `PATCH /api/orders/:id` — обновление заявки (статус, бригада, сумма)
- `GET /api/data` — каталог `{ tariffs, services, teams }`
- `PUT /api/data` — сохранение каталога

## Локальный запуск и деплой

```bash
npm install
netlify dev          # локальная проверка сайта и функций
netlify deploy --prod  # публикация в продакшн
```

Статика публикуется из папки `deploy/`, функции берутся из `netlify/functions` (объявлено в `netlify.toml`). Лендинг и админка используют одну базу Netlify Blobs.

## Правила при доработке

1. Меняй статику только в папке `deploy/` (это то, что публикуется).
2. Серверную логику — в `netlify/functions/`, JSON на вход/выход.
3. После изменения тарифов/услуг/бригад — сохраняй через `PUT /api/data`, чтобы не затирать базу вручную.
4. Не публикуй чувствительные данные (реальные пароли, ключи). Пароль админки — демо, для примера.
5. После правок прогоняй локально `netlify dev`, проверяй лендинг и админку, затем деплой.
